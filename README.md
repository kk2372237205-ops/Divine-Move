# 五子棋机器人电脑端项目

这个目录是电脑端工程，和 ESP32 中的 `main.py`、`classify.py` 分开管理。

当前版本保留基础赛成果，并已进入进阶赛的无硬件回归与实机验收阶段：

- 显示 USB 摄像头预览；
- 扫描串口；硬件默认断开，显式连接后只进入 DEBUG 调试协议；
- 自动寻找棋盘四角，并保存透视标定；
- 标定会优先拟合最外侧 13 条真实网格线（包括边界附近线段和轻微透视斜率），避免把内圈误当成棋盘外圈；
- 运行中会周期性复核棋盘几何。相机被碰、画面丢失或棋盘偏移超阈值时，程序自动停止视觉识别并作废本次标定，禁止继续生成落子坐标；
- 从实时预览保存 `.jpg` 原图，并批量生成亮度、颜色、翻转、模糊四类增强图；
- 展示取子转盘、机械臂调试的比赛入口；连接后可执行受控的空载调试动作；
- 提供 13 x 13 模拟五子棋棋盘和基础 AI；
- 从三帧稳定的摄像头棋局生成机器人黑棋计划；在人工一次授权、有效标定、已连接 DEBUG、三帧稳定与落子视觉复核同时满足时，可自动执行该计划；
- 固定竞赛坐标转换规则，避免后续把棋盘方向写反。
- 提供“标注工作台”：逐图查看原图框预览和 13×13 校正网格，程序提出候选，操作者确认/修正后再写入可追溯真值和 YOLO 标签。

## 第一次配置

在 VS Code 中打开本目录，打开终端后执行：

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Python 3.10 安装完成后，依赖装好后，执行：

```powershell
.\run.bat
```

也可以在资源管理器中双击 `run.bat`。

只接手离线标注任务的同学无需连接机器人，也无需进入完整上位机。请阅读 `标注任务交接说明.md`，依次运行根目录的 `01_首次安装标注环境.bat`、`02_标注环境自检.bat` 和 `03_启动标注工作台.bat`；完成后通过 `04_打包并返回标注成果.bat` 生成单个成果 ZIP。

需要把当前整个项目交给下一位同学时，运行 `05_打包完整项目交接包.bat`。它会生成 `handoff_exports/gobang_full_handoff_日期_时间.zip`，包含源码、活动数据集、标注历史、标定/固件备份、材料、恢复日志和规程原件，并生成逐文件 SHA-256 清单。接手者解压到新目录后，先运行 01 脚本建立 `.venv-annotation`，再运行 `scripts\verify_project_handoff.py` 自动核对清单，之后运行 02、03。包不包含 `.venv`、缓存或旧 ZIP。04 是“只回传新增标注成果”，05 才是“完整项目交接”。

VS Code 的 Python 解释器和运行任务已经指向本目录的 `.venv`。如果系统重装后尚未安装 Python 3.10，可先用 `winget install --id Python.Python.3.10 -e --source winget` 安装，再执行上面的配置命令。

## 当前界面能做什么

1. 点击“刷新串口”只会读取 Windows 列出的端口名称。
2. 从摄像头下拉框选择编号，再点击“启动预览”可以显示画面。
3. 点击“自动找棋盘”会从当前画面寻找棋盘四角，并把标定保存到 `calibration/board.json`。
4. 点击“保存原图”会把当前画面保存到 `dataset/raw/`。若要集中采集多种布局，切换到“批量采集”页，设置光照和可选备注后直接点击“开始新批次”；“自动编号”默认开启，会生成批次号，不需要手写场景编号。每摆好一个新布局后点击“保存当前帧到批次”，程序自动记录 `batch_frame=01、02...`；全部完成后点击“结束本批次”。界面会显示本批数量、自动序号和完整文件列表，不需要每张都停下来抄长文件名。整个批次期间相机必须固定；若相机被移动或碰到，应结束批次，重新“自动找棋盘”，确认新机位后再开始新批次。采集足够原图后，点击“批量生成四种增强图”会在 `dataset/augmented/` 生成亮度、颜色、水平翻转、模糊四种版本；增强默认跳过已有文件，不覆盖历史结果。
5. “基础调试”页先点击“刷新串口”，从 Windows 当前列出的端口中选择连接机械臂的 USB-SERIAL CH340 端口（9600），再点击“连接并进入调试”。连接成功后可做空载坐标移动、回零、转盘调试、气泵/电磁阀调试，以及受保护的单点或连续五黑点取放验收。五黑点坐标必须先逐点用高位空载移动实测并保存，未完成标定时按钮会拒绝动作。
6. 在“模拟棋局”页点击空位可走黑棋，程序会走一步白棋。这里的棋局不会驱动机械臂。
7. “进阶赛干运行”页与模拟棋局完全分开：它只接受摄像头连续三帧确认的真实棋盘状态。机器人执黑，程序会显示下一手的竞赛坐标及“转盘取子 - 吸取 - 抬升 - 落子 - 回待命”的完整计划。调试可使用“受监督执行”逐手验证；完成现场验收后，可一次性授权“比赛自动执行”，使每个经视觉确认的黑棋回合自动取放。两种模式都只走 DEBUG 协议，且都必须由视觉复核落子，超时、遮挡、标定失效或动作失败会安全停止。
8. 在“批量采集”页点击“打开标注工作台”可逐图核验当前 `dataset/raw/` 中的原图。先点击“采用当前候选”，再在右侧 13×13 校正网格点击交点循环空/黑/白；确认黑白类别、数量和框位置后，勾选确认框并点击“保存真值并导出标签”。真值追加到 `dataset/annotations/truth.jsonl`，程序会为源图和 brightness/color/flip/blur 四种增强图一次性写出 5 份标签，派生关系追加到 `dataset/annotations/derived_labels.jsonl`，框选预览写入 `dataset/annotation_previews/`；首次保存默认拒绝覆盖。
   已完成图片会自动锁定。如果后来发现白棋误点成黑棋（或位置、框半径有误），选中该图并点击“修改已完成标注”进入修订模式，改完后再次勾选确认并保存。程序会把旧标签/预览复制到 `dataset/annotations/history/<图片名>/revision_backup_XXXX/`，并在真值日志中追加 `revision` 版本号，绝不要求手工删除或覆盖历史文件。

相机安全门禁：每次启动预览都必须重新自动找棋盘；重新标定后必须在当前机位清空棋盘并重新保存空盘基准。预览运行期间程序会自动检查四角几何，检测到相机移动或棋盘不可见就立即停用自动识别，清除稳定棋局和旧基准缓存，并要求重新标定。比赛时即使没有人工辅助，错误机位也只会触发安全停机，不会把旧标定继续用于机械臂坐标。

## 现场联调：先验证视觉，再进入自动执行

先关闭旧版界面，再双击 `run.bat`。在新版界面按此顺序做：

1. 摄像头编号选择已验证过的 `1`，点击“启动预览”。
2. 真实棋盘清空且画面无遮挡时，点击“自动找棋盘”。目前已保存过一组四角标定，但应以当前摄像头位置重新确认。
3. 点击“保存空盘基准”。这一步必须在棋盘没有任何棋子时进行；如果 DEBUG 已连接且转盘停在取子位，程序会先将它回到料仓位，收到回执后才保存基准图。
4. 进入“进阶赛干运行”页，按“1. 准备棋盘 → 2. 开始或重置 → 3. 执行控制”的顺序操作。点击“开始对局”后，程序会对连续三帧一致的棋局更新界面；空棋盘稳定后会出现机器人第一手黑棋建议，通常为中心点。
5. 第一轮只做视觉链路验证：在建议位置手工放一枚黑棋，等待界面显示“轮到人类白棋”；再手工放一枚白棋，确认下一次黑棋建议和动作计划。此轮不是比赛自动执行验收。
6. 需要开始下一局时，先确认没有机械臂动作，再点击“准备下一局”。该按钮只清空 UI、撤销执行授权并要求新空盘基准；随后手动移走实体棋盘的全部棋子，点击“保存空盘基准”，最后再“开始对局”。
7. 终局时，虚拟棋盘正上方会突出显示“机器人获胜”“人类获胜”或“本局平局”。“胜负语音”默认开启，可在执行控制区关闭；语音不可用不会影响判胜或机械臂安全门禁。

以上只验证摄像头、棋局规则、AI 与动作计划是否衔接正确。基础调试页可在 DEBUG 模式做空载移动、转盘占空比、末端执行器和单次取子测试。通过现场标定、协议核验和受监督循环验收后，已一次授权的比赛自动执行会调用同一 DEBUG 会话完成黑棋取放；它不会自动打开串口，也不会绕过落子视觉复核或安全停止。

每次应用启动会在 `logs/sessions/` 新建一个追加式 JSONL 会话记录，保存标定、稳定棋局更新、自动授权、机器人动作、视觉复核、正常结束和安全停止等事件。日志用于验收追溯，不能替代现场视频。

## 重要安全边界

- Windows 分配的 COM 端口号会随电脑和 USB 接口变化，不能在程序、文档或固件脚本中写死。基础调试页会列出当前端口，选择连接机械臂的 USB-SERIAL CH340 端口（9600）后再连接。
- 基础调试页显式连接所选端口时会先发送 `DEBUG\n`；比赛自动执行不会自行打开串口，但仅在该 DEBUG 会话已人工连接、有效标定和视觉门禁均满足时才会发送取放计划。
- 机器人端固件的原样备份在 `firmware_backup`，只用于阅读与比对，不要把其中的文件直接上传回 ESP32。
- 已备份的 `main.py` 有真实的复位、移动、吸子和放子逻辑。任何首次动作测试都必须在机械臂周围无人的情况下，单独确认后再做。

## 已确认的通信格式

当前 ESP32 `main.py` 接收一行以换行结束的文本：

```text
x/y/z/retract\n
```

其中 `retract` 为 `True` 时是悔棋取回；其他值为正常取子、落子。该普通协议会触发真实取放动作，当前电脑端仍只保留编码，不从自动对局发送；调试页使用的是 `DEBUG` 模式下的 `x/y/z`、`P3/duty`、`RESET` 和 `EXIT`。

## 下一阶段

### 数据集验收工具

- `tmp/capture_dataset_burst.py low|medium|high N --scene-id scene_XX --notes "..."` 可从 1080P 摄像头保存一批带光照和布局记录的原图；`--edge` 用于记录棋盘边缘落子场景。连续帧只能作为同一布局的样本，不能代替改变棋子位置。
- 数据采集期间相机应固定在同一机位；相机移动会使当前四角透视标定和空盘基准不再严格适用。程序在预览和自动识别期间会复核四角几何，偏移过大时自动作废标定并停止识别。若相机被移动或碰到，先停止/结束批次，重新运行“自动找棋盘”并保存新的标定，再保存当前机位的空盘基准并开始新批次。不要把不同机位的图片直接使用同一套棋盘格标注。
- `tmp/audit_dataset.py --output tmp/dataset_audit_日期.json` 只读检查原图数量、三档光照、边缘场景、图像重复、1920x1080 分辨率、manifest 完整性、四类增强完整性和 YOLO 标注有效性；输出文件已存在时会拒绝覆盖。
- `DatasetManager.save_yolo_label()` 写入 `class cx cy width height` 格式（0=黑棋、1=白棋），会校验范围并默认拒绝覆盖已有标注。
- `pc_app/annotation_workbench.py` 是人工核验入口：程序候选只显示参考，未勾选逐点确认不会导出；框半径默认 18 校正像素，可在三档光照代表图上复核后调整。
- `export_truth_family_labels()` 会先检查四类增强图和全部目标标签，再一次性派生标签族；水平翻转只镜像横坐标并对边缘框做数值夹紧，避免浮点误差或半套标签。
- `tmp/label_grid_image.py` 可把人工确认的棋盘格坐标投影成原图 YOLO 标注，并生成框选预览。默认坐标是视觉内部的左上角 0-based `(列,行)`；若使用规程坐标，追加 `--coordinate-system competition`（右上角 1-based）。例如：

  ```powershell
  .\.venv\Scripts\python.exe -u tmp\label_grid_image.py `
    board_low_normal_20260825_174119_898718.jpg `
    --black "6,6 3,3 9,3" --white "5,6 7,6" `
    --preview tmp\label_preview_scene_01.jpg
  ```

  每个坐标必须对应图片中真实可见的棋子；`--radius`（默认 16 校正像素）只用于调整框大小。标签和预览默认拒绝覆盖同名文件，只有明确追加 `--overwrite` 才会替换。

当前取子转盘以 `6000/2800` 作为 `0°接子/90°取子`。实测取子点为 `215/189/52`，待命点为 `215/189/130`；正式取放使用短吸附时序：取子吸附约 1 秒后停泵，抵达目标点后开阀并垂直抬升，再关闭阀门。五黑点已完成真实棋子逐点验收，并保存到 `calibration/foundation_hardware.json`：左上 `239/-72/52`、右上 `369/-72/52`、中心 `304/-3/50`、左下 `239/72/52`、右下 `369/72/52`。这些是现场机械坐标标定值，不替代后续摄像机识别映射。当前相机实测为 `1920x1080`，仍应在比赛场地重新确认四角透视标定。
